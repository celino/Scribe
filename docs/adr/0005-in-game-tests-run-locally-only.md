# 0005. In-game tests run locally, never on the public CI

Status: Accepted (13/11/2026)

## Context
The adapter code can only be proven in a running KSP. KSP and Unity cannot be redistributed, so a public CI runner has
no game. A virtual display with software OpenGL was tried and is not reliable: scene loads stall for many minutes.

## Decision
- Unit tests, the feature matrix check and the Python tool tests run on every push, on any CI.
- In-game rounds (`tests/ingame`, `tools/run-ingame-all.sh`) need a KSP 1.12.5 the person owns and a real display and
  GPU. They print `ASSERT Fnn PASS|FAIL` lines that `check_round.py` turns into an exit status.
- The repo carries the recipe only: a Dockerfile with no game files, a script that builds a minimal test install with
  hardlinks, and a synthetic save generated by `make-save.py`.

## Consequences
- A green public CI proves the logic, not the integration. The README and `docs/TESTING.md` say so.
- Before a release, the maintainer runs all rounds on a machine with the game and records the result in the CHANGELOG.
